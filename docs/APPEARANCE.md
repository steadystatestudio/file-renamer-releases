# Desktop appearance

All interface text uses the configured desktop UI font family and effective size. Headings use weight for emphasis. This includes buttons, tables, menus, tooltips, dialogs, Help and status. Typography inside actual documents, photos and exported content is unchanged. Window decorations belong to the operating system.

Primary actions, enabled toggles, selected items and progress use the native personalization/selection accent. An accent can differ from the titlebar close-button color. Normal secondary actions remain neutral. Text on accent fills uses contrasting black or white; focus and disabled states remain distinct.

Settings provides System/Light/Dark, system/custom font and size (6–72 points), and system/custom accent. Save applies staged choices; Cancel discards them. Reset appearance to System affects appearance only and takes effect on Save. It retains subfolder preferences, presets and history. Refresh system settings re-reads the desktop while preserving explicit overrides and unsaved choices. Production Settings does not expose a diagnostic-copy control.

Windows uses native UI settings. Linux resolves font, light/dark and accent independently: app override, explicitly selected qt6ct configuration, supported desktop preferences, captured Qt, then a readable fallback. Desktop providers include portal color preferences, KDE settings in KDE sessions, and optional GTK 3 settings including X11 integration. The GTK reader is a bundled native helper; no system Python or PyGObject is required. Missing integration or failed helpers leave the app usable. Portal and supported native notifications can refresh settings automatically; use Refresh system settings when a desktop sends no usable notification.

Display scaling belongs to Qt. Provider-specific font units and GTK font DPI/widget scaling are normalized once; KDE/qt6ct font values retain their Qt units. Layouts measure the resulting text and do not shrink it to fit. On a monitor too small for the useful minimum, configuration can reflow and work areas scroll while actions and status remain available. Changing Light/Dark preserves the selected font. Application-owned Qt file and color dialogs follow the same resolved font and theme; operating-system window decorations remain native.

Rename stays centered while space permits, then stops beside the neighboring controls with normal gaps. The complete measured control row determines the minimum width. Ordinary forms fit their active controls. Text-heavy rule editors allow horizontal resizing and store separate preferred logical widths, changed only by user resizing. Font/theme changes, mode switches and temporary monitor constraints do not overwrite those widths. Long catalogues and content retain useful scrolling.

If desktop integration is unavailable, the captured native palette is retained, then a readable Studio blue is the final fallback. The app records appearance sources and fallback reasons in `appearance.json` in its local application-data folder. That diagnostic contains appearance settings, not document paths or content. A fallback is not proof of a verified system match.
